SDR BEAMFORMING PROJECT
Added Software Structure and Mock Data Guide

PURPOSE
-------
This project contains software for controlling and testing a software-defined
radio (SDR) beamforming system. The software can work in two modes:

1. Mock-data mode, which allows the software to be developed and tested
   without a physical PlutoSDR.
2. Real-SDR mode, which communicates with a PlutoSDR when the hardware is
   available.

The project is organized into several Python files. Each file has a specific
role so that the main experiment does not have to contain every calculation,
configuration setting, plotting function, and data-logging function in one
large script.

C:\x\sdr-beamforming-main\Toolbox\PlutoSDR\TestScripts


1. plotFFT.py
-------------
plotFFT.py is the main experiment and testing script. It brings together the
other software modules and controls the overall phase-sweep experiment. In
normal operation, it obtains two receiver signals, applies different phase
shifts to one signal, combines the two signals, calculates the FFT, and
determines which phase produces the strongest received signal.

The script can use either simulated data or a real PlutoSDR. When mock-data
mode is enabled in experiment_config.py, plotFFT.py uses the simulated IQ
signals from mock_data.py instead of requesting data from the radio. This
allows the rest of the processing to be tested before the physical hardware
is available. When mock mode is disabled, plotFFT.py uses plut_config.py to
configure the PlutoSDR and receive actual IQ data.

plotFFT.py also produces the FFT display and records measurements from the
phase sweep. It can identify the strongest FFT peak and associated
information such as peak frequency, noise floor, and signal-to-noise ratio.
The script therefore acts as the main experiment coordinator rather than
containing every individual calculation itself.


2. signal_processing.py
-----------------------
signal_processing.py contains the mathematical and signal-processing
operations used by the main experiment. Its purpose is to keep calculations
separate from the experiment-control code in plotFFT.py.

The module processes the IQ samples into an FFT spectrum expressed in dBFS,
combines receiver channels, applies a phase delay, and calculates useful
measurements such as the FFT peak, peak frequency, noise floor, and SNR.
Keeping these operations in one module makes the calculations easier to
test, reuse, and modify without changing the overall experiment.

The module is used for both mock data and real SDR data. This is important
because the same processing steps can be applied to simulated signals before
the hardware is available and to actual signals after the PlutoSDR is
connected.


3. experiment_config.py
-----------------------
experiment_config.py contains the user-editable experiment settings. It is
intended to provide one central location for changing the conditions of an
experiment instead of requiring the user to search through several scripts.

The settings include whether mock data is being used, sampling rate, number
of samples, RF bandwidth, receiver and transmitter frequencies, receiver
gain, transmitter gain, phase-sweep settings, antenna information, test
environment, distance, environmental loss, output file names, and plotting
settings. For example, USE_MOCK_DATA = True tells the project to use
simulated signals instead of connecting to a physical SDR.

This file does not perform the experiment itself. It supplies the values
that the other modules use. This makes it easier to repeat an experiment
with different conditions while keeping the software structure consistent.


4. mock_data.py
--------------
mock_data.py creates simulated IQ data when a physical PlutoSDR is not
available. IQ data represents the signal information that an SDR receiver
would normally provide to the processing software. The mock-data function
creates two simulated receiver signals and adds a controlled phase
difference between them.

The simulation also includes simplified effects for signal amplitude,
distance, environmental attenuation, and random noise. This allows the
software to imitate some of the conditions that may be investigated during
the real experiments. For example, the simulated distance or environmental
loss can be changed to observe how the calculated received signal changes.

Mock data is not a replacement for real RF measurements. The simulated
noise is generated by the program and is not actual environmental noise.
The current model does not reproduce every real-world effect, such as
multipath reflections, actual electromagnetic interference, antenna
imperfections, cable losses, hardware noise, or other changes in the RF
environment. Mock mode should therefore be considered a software-testing
and preliminary-analysis tool.


5. pluto_config.py
------------------
pluto_config.py contains the PlutoSDR-specific hardware configuration.
Instead of putting all of the radio setup commands directly into plotFFT.py,
the main script can call configure_pluto() to create and configure the
radio.

The configuration includes the PlutoSDR connection address, enabled receiver
channels, sample rate, RF bandwidth, receive frequency, receiver gains,
receive buffer size, transmit bandwidth, transmit frequency, transmit
gains, and transmit buffer settings. These values are taken from
experiment_config.py.

This module is only needed when using the physical PlutoSDR. When mock mode
is enabled, the program should not attempt to create or configure the SDR.
This separation allows the software to be developed and tested without
requiring the radio to be connected.


6. utilities.py
---------------
utilities.py contains small general-purpose functions that are useful in
multiple parts of the project. Examples include creating timestamps,
printing a formatted program banner, generating a test tone, and creating
the frequency axis used by FFT plots.

The purpose of this module is to prevent simple helper functions from being
repeated throughout the project. For example, the function that creates the
test tone can be called by the main experiment instead of rebuilding the
time array, sine wave, and complex IQ signal every time the test tone is
needed.

These functions are not specific to one particular phase-sweep experiment.
They are general tools that can be reused by other SDR tests as the project
grows.


7. data_logger.py
-----------------
data_logger.py provides the project's basic CSV data-logging system. Its
DataLogger class creates or adds to a CSV file and automatically records a
timestamp along with the values supplied by the experiment.

A logger records
the overall result of the experiment in ExperimentSummary.csv. The detailed file
can contain the best phase and the most important final measurements.

Separating the logging system from plotFFT.py means that the main experiment
does not have to contain all of the file-writing code. The same DataLogger
can also be reused later for RF-harvester measurements or other experiments.


8. plotting.py
--------------
plotting.py contains functions used to display experimental results. Its
purpose is to keep graphing commands separate from the main experiment and
signal-processing calculations.

For the FFT experiment, plotting functions can display the frequency
spectrum, signal level, and current phase being tested. Keeping the plotting
code in its own module makes plotFFT.py easier to read and allows the same
plotting functions to be reused by other experiments.

The graphs are intended to help the team understand how the received signal
changes as the phase relationship between the receiver channels is changed.
The plotted results are based on either mock data or actual SDR data,
depending on the operating mode.


HOW THE FILES WORK TOGETHER
---------------------------
The overall process can be understood as a sequence:

experiment_config.py
        |
        | provides experiment settings
        v
plotFFT.py
        |
        +---- mock_data.py
        |       |
        |       +---- creates simulated IQ data
        |
        +---- pluto_config.py
        |       |
        |       +---- configures the real PlutoSDR
        |
        +---- signal_processing.py
        |       |
        |       +---- processes IQ data and calculates measurements
        |
        +---- plotting.py
        |       |
        |       +---- displays FFT and experiment results
        |
        +---- data_logger.py
        |       |
        |       +---- saves measurements to CSV files
        |
        +---- utilities.py
                |
                +---- provides reusable helper functions


MOCK DATA MODE
--------------
When USE_MOCK_DATA = True, the project does not need a physical PlutoSDR.
plotFFT.py obtains simulated IQ data from mock_data.py. The simulated data
is then passed through the same general signal-processing and plotting
workflow used for the real experiment.

This makes it possible to test the software structure, FFT calculations,
phase sweep, graphs, measurement calculations, and CSV logging before the
hardware is available. It also allows preliminary tests of how changing
distance and environmental-loss assumptions affects the simulated results.

Mock data should not be presented as measured experimental data. It is a
controlled simulation intended to verify and develop the software.


REAL SDR MODE
-------------
When USE_MOCK_DATA = False, plotFFT.py uses pluto_config.py to configure a
physical PlutoSDR. The SDR receives actual IQ samples and the same
signal-processing functions are then used to analyze those samples.

The real experiment will therefore use a similar software workflow to the
mock experiment. The main difference is the source of the IQ data: the mock
mode creates it in software, while real-SDR mode receives it from the
physical radio.


RF HARVESTER EXTENSION
----------------------
A future RF-harvester measurement module can be added separately from the
SDR processing software. The PlutoSDR is used to generate or receive RF
signals, while the RF harvester converts received RF energy into DC energy.
A measurement device can then be used to measure the harvester's DC output.

The future measurement software can record values such as DC voltage,
current, load resistance, calculated DC power, transmission distance,
frequency, and environmental conditions. This should remain separate from
plotFFT.py because an FFT peak and harvested DC power are different
measurements.


IMPORTANT NOTE
--------------
The mock-data system is useful for software development and preliminary
analysis, but simulated results should not be treated as proof of actual RF
performance. Final conclusions about transmission distance, environmental
effects, beamforming performance, and harvested energy should be based on
measurements made with the physical SDR, antennas, RF harvester, and
appropriate measurement equipment.
